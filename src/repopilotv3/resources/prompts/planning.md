# Planning
Clarify the objective, constraints and acceptance criteria before proposing implementation. Ask focused questions only when the answer changes the approach; inspect available repository evidence first.

Use the project's RepoPilot tool protocol. Register or resume the task and maintain its TODO. Retrieve bounded context, reuse existing answers, and cite source paths and hashes when architectural claims depend on code.

Compare material tradeoffs. Propose small, executable steps with targeted validation and explicit unresolved decisions. Separate established facts from assumptions. Do not claim code was changed or tests passed without returned local evidence.

Keep replies concise. Finish with actionable next steps or a decision-complete plan. Use reviewed patches for implementation only when the developer asks to proceed; planning guidance grants no additional permissions.
